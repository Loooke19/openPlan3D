# 医院导览 Demo：程序化材质与光照实现说明

更新日期：2026-09-09。本文依据当前 `preview/scene3d.js` 的实际实现编写，不是尚未落地的设计方案。

后续更新：地图工具现已提供 3D 外观实时调节，默认值在 `preview/appearance.js`。下文固定数字描述的是默认效果；颗粒倍数、砖尺寸、墙裙高度已改用共享 shader uniform，光照/曝光/墙色/地面色可运行时修改。恢复默认可回到基准参数。设置仅存本机浏览器，不随地图 JSON 导出。

## 1. 一句话说明

这套效果不是“找到一张特别真实的贴图”，而是把医院走廊最有辨识度的几个视觉要素拆开，用世界坐标驱动的着色规则、标准材质和适量光照组合出来：

**浅色哑光墙面 + 极弱颗粒 + 浅绿墙裙 + 深色踢脚线 + 地砖接缝 + 有方向的明暗。**

技术本身并非独家，也不意味着其他模型无法实现。真正值得保存的是本项目的取舍、坐标约定、参数组合和检验方法。有明确说明后，其他开发者或模型可以复现，不必反复凭感觉试错。

这里的目标是“清楚、可信、便于找路”，不是照片级装修效果。墙面是背景，房间名称和导航路线才是主角。

## 2. 实际用了什么，没有用什么

| 项目 | 当前实现 |
| --- | --- |
| 渲染器 | 本地 Three.js，WebGLRenderer |
| 建筑材质 | MeshStandardMaterial，非金属材质 |
| 材质定制 | onBeforeCompile 注入少量 GLSL |
| 纹理位置依据 | 世界坐标，不依赖手工展开 UV |
| 墙面颗粒 | 正弦函数产生的细微颜色变化 |
| 墙裙及踢脚线 | 按世界坐标高度分区乘色 |
| 地砖 | 世界坐标网格、灰缝和导数抗锯齿 |
| 光照 | 一盏半球光、一盏方向光 |
| 阴影 | 2048×2048 阴影贴图，PCFSoftShadowMap |
| 显示处理 | sRGB 输出、ACESFilmicToneMapping |

**没有使用：**外部墙地贴图、AI 生成墙地图片、法线贴图、凹凸贴图、位移贴图、环境 HDR、全局光照、光线追踪、屏幕空间环境遮蔽。

注意：后来增加的门牌是 Canvas 绘制文字后生成的 CanvasTexture。这与墙地材质不同，不能把整个场景概括为“完全没有纹理图片”。

## 3. 为什么先选世界坐标

### 3.1 本项目坐标约定

PDF 中的位置是归一化的二维坐标，转换为三维时：

```js
worldX = normalizedX * pdfWidth  - centerX;
worldY = height;
worldZ = normalizedY * pdfHeight - centerZ;
```

- X、Z 是地面平面，Y 是竖直高度。
- 房间、走廊、门位、导航路线共享这套坐标。
- 普通墙高为 19，行走视点高度为 12。
- 这些是图纸/演示单位，不是米，不能直接用于施工或真实距离估算。

### 3.2 为什么不直接用每面墙的 UV

墙体使用同一份单位立方体几何，通过 InstancedMesh 缩放、旋转、平移，形成不同长短的墙段。

如果直接把一张纹理完整铺到每面墙的 0～1 UV 上，又不单独调整重复次数，长墙的颗粒会被拉长，短墙的颗粒会被压缩。每面墙还可能从不同位置重新开始铺纹理。

现在不问“这是墙面的百分之几”，而问“这个像素对应的三维位置是多少”。同样的空间距离会得到同样的纹理尺度，地砖网格也自然连续。

### 3.3 实例变换不能漏

当前顶点着色器注入代码：

```glsl
varying vec3 hospitalPosition;

// 以下位于顶点主函数内。
vec4 hospitalWorld = vec4(transformed, 1.0);
#ifdef USE_INSTANCING
  hospitalWorld = instanceMatrix * hospitalWorld;
#endif
hospitalPosition = (modelMatrix * hospitalWorld).xyz;
```

顺序是：**局部顶点 → 当前实例变换 → 对象世界变换**。

漏掉 `instanceMatrix`，同一个单位立方体被缩放成不同墙体后，纹理仍可能按原始小立方体计算。当前单独计算这个位置，也避免依赖 Three.js 内部 `worldPosition` 变量是否在特定编译条件下存在。

限制：世界坐标纹理适合静态建筑。若未来整体移动模型，纹理会随其在世界空间的位置重新采样；需要让纹理固定在楼体上时，应改为统一的楼体坐标。倾斜墙体和复杂可动模型也不能直接照搬当前“Y 表示离地高度”的假设。

## 4. 墙面：不是增加模型面数，而是微调颜色

### 4.1 基础材质

```js
new THREE.MeshStandardMaterial({
  color: '#e2e6e3',
  roughness: 0.88,
  metalness: 0
});
```

浅灰绿色底色负责医院墙面的整体倾向；高粗糙度让它呈现哑光表面，避免塑料或金属感。roughness 是光照反射参数，不是“颗粒强度”。

### 4.2 颗粒公式

```glsl
float grain =
  sin(hospitalPosition.x * 42.0 + hospitalPosition.z * 37.0)
  * sin(hospitalPosition.y * 51.0);

diffuseColor.rgb *= 0.97 + grain * 0.025;
```

拆开看：

1. X、Z 混合项让水平空间位置影响纹理。
2. Y 项增加竖直方向变化，避免只有单向条纹。
3. 两个正弦相乘，得到范围约为 −1～1 的规则细密变化。
4. 最终颜色乘数落在 **0.945～0.995**，只有很小的亮度差。

这不是随机噪声算法，更不是扫描得到的涂料纹理。它是周期性数学图案，只是在当前尺度和低对比度下，呈现近似颗粒的视觉效果。

**克制是关键：**这里没有让颗粒改变表面法线，也没有真的把墙面顶点顶起来，所以不会出现夸张凹凸和强烈闪光。如果把 `0.025` 大幅提高，会更像斑驳水泥，而不是清洁的医院涂料。

注意：当前墙面高频正弦没有专门做导数过滤。某些视角或分辨率下可能出现摩尔纹/闪烁，不能保证在所有设备上稳定。若出现这种问题，应先降低频率或按屏幕导数衰减颗粒，而不是继续提高渲染分辨率。

## 5. 墙裙、分隔线、踢脚线：同一面墙上的高度分区

```glsl
if (hospitalPosition.y < 1.15)
  diffuseColor.rgb *= vec3(0.39, 0.47, 0.45);
else if (hospitalPosition.y < 7.0)
  diffuseColor.rgb *= vec3(0.80, 0.88, 0.85);

if (hospitalPosition.y > 6.7 && hospitalPosition.y < 7.2)
  diffuseColor.rgb *= vec3(0.54, 0.66, 0.59);
```

| 高度范围 | 效果 | 意义 |
| --- | --- | --- |
| Y < 1.15 | 深色踢脚线 | 让墙根与地面分开，提供空间边界 |
| 1.15 ≤ Y < 7.0 | 浅绿墙裙 | 提供医院走廊的识别特征和连续水平参照 |
| 6.7 < Y < 7.2 | 较深分隔带 | 强调上下墙面分界 |
| 其余高度 | 浅色墙面 | 保持明亮、安静，衬托门牌 |

这里的颜色是**乘数，不是最终色值**。例如浅绿墙裙的 R 通道压低得比 G 通道更多，因此在原本浅灰绿底色上进一步产生绿色倾向。最终显示还会受到光照和色调映射影响。

两个 `if` 有意叠加：6.7～7.0 区域先乘墙裙色，再乘分隔带色；7.0～7.2 只乘分隔带色，因此带内上下部分并非完全相同颜色。

当前这些结构只是颜色分区：**没有另建凸出的扶手、墙裙板或踢脚线几何**。近看不会产生独立厚度、轮廓和自阴影。视觉上足够传达材料层次，但不应称为完整装修建模。

## 6. 地砖：把无限地面变成规则网格

基础地面使用 `roughness: 0.65`、`metalness: 0`；主地面底色为 `#fbfcfa`。房间仍使用各自功能分区底色，再叠加同一套地砖规则。

### 6.1 确定砖的尺寸

```glsl
vec2 tile = hospitalPosition.xz / 12.0;
```

除以 12，表示每 12 个世界单位重复一个网格单元。不是 12 厘米，也不是经过测量的真实砖尺寸。

### 6.2 找到离接缝的距离

```glsl
vec2 edge = abs(fract(tile - 0.5) - 0.5);
```

`fract()` 取小数部分，让图案每隔一个单位重复。这个表达式得到各轴上到最近整数网格线的距离：在接缝处为 0，在砖块中间达到 0.5。X、Z 两个方向组合，就形成方格。

### 6.3 处理远处与斜视时的细线

```glsl
vec2 aa = max(fwidth(tile), vec2(0.001));
vec2 seam = 1.0 - smoothstep(vec2(0.018), vec2(0.018) + aa, edge);
float grout = max(seam.x, seam.y);
```

- `fwidth()` 估计相邻屏幕片元之间坐标的变化量。
- `smoothstep()` 用平滑过渡取代硬切边。
- `max(seam.x, seam.y)` 合并横竖接缝，交叉处不会简单加倍变黑。
- `0.018` 是接缝的名义半宽，中心到两侧的基础总宽约为 `2 × 0.018 × 12 = 0.432` 世界单位，另有抗锯齿过渡区。

这样能缓解细线在透视远处出现锯齿和跳动。它不是完整的解析预过滤方案；特别远处仍可能发生对比度变化，不能说彻底解决所有混叠。

### 6.4 最后叠加颜色

```glsl
float grain = sin(hospitalPosition.x * 31.0)
            * sin(hospitalPosition.z * 39.0);
diffuseColor.rgb *= 1.0 - grout * 0.18 + grain * 0.012;
```

接缝中心约压暗 18%；表面颗粒幅度仅为 1.2%。地砖颗粒比墙面更弱，避免影响绿色导航线。

当前地砖也没有真实凹缝、倒角、凹凸法线或镜面倒影。规则图案与明暗已经提供足够空间尺度感，没有必要为 Demo 给每块砖单独建模型。

实现细节：当前 `flatPolygon()` 统一使用地面材质，建筑底座和庭院底面也会经过同一套规则。如后续要求严格区分草地、台面、底座，应再拆分材质，不能宣称当前已经按所有真实材料分类。

## 7. 为什么保留标准材质，只插入颜色规则

在 `surfaceMaterial()` 中，通过 `onBeforeCompile` 修改标准材质生成的 shader：

```js
shader.fragmentShader = shader.fragmentShader.replace(
  '#include <color_fragment>',
  '#include <color_fragment>\n' + surface
);
```

自定义规则在基础颜色阶段修改 `diffuseColor.rgb`，后续仍由 Three.js 标准材质处理光照、粗糙度和阴影。不必从零编写整套光照算法，也不会把墙面画成完全不受光的平面色块。

墙面和地面使用不同程序缓存键：

```js
material.customProgramCacheKey = () => `hospital-${kind}-v1`;
```

这是为了区分两种不同 shader 源码，而不是只区分颜色。若将来改变 shader 结构或增加编译变体，需要同步管理缓存键和材质更新。

移植注意：shader chunk 名称、替换位置、API 行为与 Three.js 版本有关。本项目使用本地固定版本，升级时应重新验证编译和视觉效果；不能保证这段字符串替换跨所有版本原样有效。

## 8. 光照：亮度底座与方向感分开负责

### 8.1 半球光负责“不黑成一片”

```js
new THREE.HemisphereLight('#ffffff', '#b8bfc4', 1.8);
```

半球光根据表面朝向，在上方白色和下方灰蓝色之间提供近似环境照明。它让墙面即使不受主光照射，也不会完全黑掉。

它不是模拟天花板灯具，也不计算墙壁遮挡后的真实间接照明。可以把它理解为廉价、可控的亮度底座。

### 8.2 方向光负责“看得出体积”

```js
const sun = new THREE.DirectionalLight('#fff5e8', 2.2);
sun.position.set(-400, 900, 300);
```

方向光稍微偏暖，不同朝向墙面得到不同明暗；配合阴影，建立空间结构。这里模拟的是一个可读性良好的主光方向，并非真实医院灯光测量结果。

当前是无顶模型，因此允许上方主光进入。未来若增加封闭天花板，需要重新布置室内光源，不能指望原参数自动适用。

### 8.3 阴影必须同时配置投射和接收

```js
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap;
sun.castShadow = true;
sun.shadow.mapSize.set(2048, 2048);
sun.shadow.normalBias = 0.4;
wallMesh.castShadow = true;
wallMesh.receiveShadow = true;
floorMesh.receiveShadow = true; // 此处为地面对象的示意名称
```

方向光阴影相机范围：左右、上下均为 ±650，near 为 1，far 为 2200。

- 2048 分辨率是在清晰度与开销之间选取的 Demo 参数，不代表所有设备都适合。
- PCFSoft 对阴影采样进行过滤，减弱硬锯齿边缘；不是物理上由大面积灯源产生的真实半影。
- `normalBias` 可缓解自阴影条纹；过大可能让阴影脱离墙根或漏光。
- 固定 ±650 的覆盖范围只适合当前尺度。更大新图应按建筑边界重新计算，否则部分墙不在阴影范围内。

## 9. 输出色彩与性能选择

```js
renderer.outputColorSpace = THREE.SRGBColorSpace;
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.setPixelRatio(Math.min(window.devicePixelRatio || 1, 2));
```

sRGB 输出与 ACES 色调映射共同影响最终显示，因此单独复制墙面十六进制颜色，不一定得到同样效果。当前没有另外设置 `toneMappingExposure`，使用当前 Three.js 默认值。

像素比上限为 2，避免高分屏无限增加像素开销。墙体使用 InstancedMesh，减少大量独立墙体对象的绘制开销；墙地无需外部图片下载。

但“程序化”不等于“没有成本”：每个片元仍要计算函数，阴影还有额外渲染和显存开销。当前没有做移动设备 GPU 性能验收，也没有实现只在变化时更新阴影的优化。

门牌和箭头则使用不受灯光影响的基础材质并关闭色调映射，优先保证文字、方向符号的对比度。这是导览系统中“建筑负责空间感，信息负责清晰度”的分工。

## 10. 为什么这组效果比较合适

下面是设计判断，不是经过用户实验验证的结论：

1. **大尺度结构先成立。** 上下墙面的分区、墙根和地面网格，即使不看颗粒，也能让空间不再像灰色积木。
2. **细节低对比。** 颗粒只增加一点变化，不争夺注意力。
3. **颜色数量少。** 灰白、浅绿和深绿形成连贯的医院气质，没有混入复杂木纹、大理石或强反光材料。
4. **连续水平线帮助观察转角。** 墙裙分隔带在转弯时提供稳定的透视线索。
5. **明暗足够，但不戏剧化。** 环境亮度较高，导航信息不会淹没在暗部。
6. **所有细节共用空间尺度。** 更换长短不同的墙段，不会突然出现被拉伸的纹理。

不是越真实越好。对目前的导览用途，增加污渍、镜面反射、强烈景深或复杂装饰，可能反而妨碍找路。

## 11. 怎样调整，才不破坏现在的感觉

| 想调整的效果 | 优先调整 | 注意事项 |
| --- | --- | --- |
| 墙面更干净 | 颗粒幅度 0.025 降低 | 不要先把所有墙面改成纯白 |
| 墙面颗粒更明显 | 小幅提高颗粒幅度 | 先检查走动画面是否闪烁 |
| 墙裙更高或更低 | 7.0 与分隔带的 6.7、7.2 一起移动 | 踢脚线不必跟着变化 |
| 砖块更大 | 分母 12 增大 | 固定 0.018 时，接缝世界宽度也会变大 |
| 缝更细、更淡 | 0.018 降低、0.18 降低 | 两者分别影响宽度与对比度 |
| 整体更亮 | 先微调光照强度 | 不要同时改底色、光强和曝光，难以定位原因 |
| 体积更清楚 | 微调主光方向或半球光强度 | 降低环境光可能使阴影处门牌背景变暗 |
| 帧率不足 | 先检查阴影、像素比、对象数量 | 不应第一步就牺牲文字可读性 |

建议每次只改一类参数，用相同路线、相同暂停位置作前后对比。不要一边改模型尺度，一边改材质频率，否则无法判断改善来自哪里。

## 12. 移植到新 PDF 地图时的检查清单

- [ ] 保持 XZ 地面、Y 高度的坐标约定。
- [ ] 核对新图单位，统一调整墙高、视点高度、砖尺寸、纹理频率和阴影范围。
- [ ] 若坐标整体放大 k 倍，要保留同样相对效果：高度阈值和砖尺寸乘 k，正弦频率除以 k。
- [ ] 墙实例的世界位置包含 instanceMatrix，不只使用单位几何坐标。
- [ ] 地面开启接收阴影，墙开启投射与接收阴影。
- [ ] 保留标准材质光照流程，在基础颜色阶段加入规则。
- [ ] 墙面、地面 shader 变体使用不同缓存键。
- [ ] 保留 sRGB、ACES 配置后再评估颜色。
- [ ] 近距离检查颗粒，远距离检查地砖混叠，转角检查阴影瑕疵。
- [ ] 检查俯视、第一人称、暂停和移动时的效果，不只看一张截图。
- [ ] 确认文字和导航箭头仍然优先可读。

## 13. 可直接交给其他模型的交接要求

> 请以现有 `preview/scene3d.js` 为基准复用医院程序化材质，不重做视觉风格。保留浅色哑光墙、弱颗粒、浅绿墙裙、深色踢脚线、灰色地砖接缝及柔和主光。墙地采用世界坐标着色，正确处理 InstancedMesh；保留标准材质的光照与阴影逻辑。先确认新地图尺度，再统一调整高度、砖尺寸、纹理频率及阴影范围。不要引入外部墙地贴图，不要把颜色颗粒误称为法线凹凸，不要把演示高度当成真实米数。保留门牌与路线的高可读性。每次只调整一类参数，并用相同的俯视和行走位置验收；说明代码改动、测试结果及未验证设备。
