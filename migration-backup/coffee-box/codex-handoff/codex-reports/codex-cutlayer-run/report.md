# 切层提速

三个低画质切层场景均达到 ≤3 秒，四个浏览器场景全部通过。在上次未提交改动上完成验证，保留已有楼梯、标牌和 kit 改动。

实现：路线当前段达到 35% 时预取下一层 nav 数据并提前构建场景；请求去重，已访问楼层保留场景，切层只切换可见性；淡出至淡入结束暂停连续渲染，新楼层先绘制一帧再淡入。均为通用规则。原上楼请求仅需 21–29ms，主要瓶颈是同步建场景和恢复渲染。

测速使用 Chromium/SwiftShader、`quality=low&kit=1`，淡出、淡入各 300ms。沿用上次原实现基线，本次重新测量优化结果；下面单位为秒，合计从淡出开始至遮罩完全透明。

优化后上楼预取分别提前 9.295/7.268 秒，请求耗时 44.8/19.1ms，场景预建 6.499/6.971 秒，均在淡出前完成；下楼直接复用已访问场景。三个场景的显示切换分别仅需 17.4/18.0/14.3ms，切层期间无场景重建、无重复目标楼层请求。原始分段记录见 `verification/cutlayer-{before,after}-{sim-up,fp-up,fp-down}.json`。

验证：

- 专项单元测试 **4 文件、49 项通过**：场景签名、路线进度、楼梯方向、楼梯几何；日志 `verification/cutlayer-tests.log`。
- 浏览器 **4 场景通过**：模拟上楼、第一人称上楼、第一人称下楼、取消加载。首轮模拟通过后后台服务进程中断，恢复服务并重跑剩余 3 项，均通过；日志 `verification/cutlayer-browser-after.log`、`verification/cutlayer-browser-retry.log`。
- guard **PASS**；15 个 GLB 一致，holeCuts/holeKeeper 所在 **239 行代码逐字不变**。guard 的 2 条既有告警是标牌导入和字段差异，已人工核对；记录 `verification/cutlayer-guard.log`、`verification/cutlayer-kit-preservation.json`。
- P1 截图：[切层前](shots/P1-cutlayer-before.png)、[切层后](shots/P1-cutlayer-after.png)，已确认分别显示 1F、3F 且遮罩透明。dev 端口 5322，Playwright 端口 4192。

剩余：预建仍占用主线程约 6.5–7 秒，本轮将其移出切层关键路径；缓存也增加内存占用。第一人称上楼距 3 秒上限仅约 0.10 秒，不能保证更慢设备仍达标。未推送。
